### Changes in v2.9.65 (Build 223):
- **Call Collision & Call Waiting Guard**: Protected active call sessions from being destroyed when a second incoming call arrives. If the user is on an active call (`ANSWERED`) or connecting (`CALLING`), the second call is automatically declined with `reason = "busy"`, a gentle in-ear call-waiting pip is played to the user without interrupting ongoing speech, and a missed call notification is logged.
- **"User Busy / On Another Call" Feedback**: When a call is declined due to user busy state, the caller's screen explicitly displays **"User Busy / On Another Call"** (instead of generic "Call Declined") and plays standard telecom busy signal (`ToneGenerator.TONE_SUP_BUSY`), giving instant clarity to the caller.
- **Cross-Call Teardown Protection**: Fixed an issue where receiving a `cancel_call`, `missed_call`, or `call_declined` push for an old or different call ID would cancel `ActiveCallService` or disconnect `LksConnectionService` on the user's ongoing call.
- **Android 14+ (API 34/35) Foreground Service Alignment**: Added `phoneCall` to `android:foregroundServiceType` in `AndroidManifest.xml` and included `ServiceInfo.FOREGROUND_SERVICE_TYPE_PHONE_CALL` in `ActiveCallService.kt` to ensure full compliance with Android 14+ background execution policies.
- **Optimized Push Payload**: Cloudflare worker and `WebRtcEngine.kt` now forward the `reason` attribute to keep caller and callee devices synchronized in 0ms.
